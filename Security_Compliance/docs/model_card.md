# Model Card — Demo Risk-Flag Classifier

## Purpose
Illustrates a simple, explainable risk-classification workflow inside the
Model Validation tab of the compliance demo app. **It is not a clinical or
regulatory decision-support tool** and must never be used to influence real
patient care, product safety determinations, or regulatory submissions.

## Data lineage
- 100% synthetic data generated by `generate_synthetic_data.py`, fixed seed
  (`SYNTHETIC_DATA_SEED`, default 42), regenerable at any time.
- Features are derived per `safety_reports` row from that patient's synthetic
  lab and adverse-event history:
  - `abnormal_lab_count` — count of that patient's lab results more than 2
    standard deviations from the per-test synthetic baseline mean.
  - `n_adverse_events` — count of recorded adverse events for that patient.
  - `has_serious_ae` — 1 if any of the patient's adverse events is `Serious`.
- Label: `risk_flag`, itself synthetically generated with a higher probability
  for patients seeded as "serious-AE" or "abnormal-lab" during data
  generation — i.e. the label and features share a common synthetic cause by
  construction. This is intentional for a demo (it gives the model something
  learnable) but means reported accuracy has no bearing on real-world
  predictive power.

## Model
Logistic regression (`scikit-learn`), trained fresh on every Model Validation
tab load, 70/30 train/test split, `random_state=42`.

## Validation
- Accuracy and a confusion matrix are computed against the synthetic held-out
  test split and displayed live in the app.
- No external or production validation exists or is planned; none is
  appropriate for a demo model.

## Known limitations
- Trained on a few hundred synthetic records; not statistically robust.
- Features and label are both synthetic and share generation-time
  correlation — this model would not transfer to real data.
- No fairness, calibration, or subgroup analysis has been performed.
- Retrained from scratch on every app load; no versioning or drift monitoring
  of the model itself (only of the underlying lab data, via the Drift
  Monitoring tab).

## Prohibited uses
- Any use on real patient, product, or clinical data.
- Any use that informs an actual clinical, regulatory, or safety decision.
- Any deployment outside an internal, access-controlled demo environment.
